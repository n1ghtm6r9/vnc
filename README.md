# vnc — клиент «Общего экрана» Mac для Windows

Клиент VNC на Rust для Windows 11. Подключается к «Общему экрану» macOS (RFB 003.889), входит под пользователем macOS и показывает Retina-экран Mac (например, 3456×2234) в окне Windows. Масштабирование идёт на видеокарте. Интерфейс на русском.

## Стек

- Rust 2024, cargo-nextest для тестов.
- winit 0.30 — окно и ввод; wgpu 30 (DirectX 12) — вывод и масштабирование; egui 0.37 — форма входа, панель, окно переподключения.
- arboard — буфер обмена; windows — перехват клавиши Windows и диспетчер учётных данных.
- NVDEC (`nvcuvid.dll` из драйвера NVIDIA) — декодирование HEVC 4:4:4 в режиме High Performance.
- fdk-aac 0.8 (Fraunhofer FDK AAC) — декодирование звука AAC-ELD; cpal 0.18 (WASAPI) — вывод звука.
- Протокол RFB, вход и декодеры написаны в этом репозитории.

## Структура

| Путь | Что внутри |
|---|---|
| `apps/client` | приложение `vnc.exe`: окно, форма входа, панель, переподключение, ввод, буфер обмена, настройки, иконка |
| `packages/rfb` | сообщения протокола RFB: чтение и запись |
| `packages/rfb_auth` | вход: Apple Remote Desktop (тип 30, пользователь и пароль macOS) и VNC-пароль (тип 2) |
| `packages/rfb_decode` | декодеры Raw, CopyRect, RRE, Hextile, Zlib, Tight (с JPEG), ZRLE, Apple MVS, курсор, смена размера экрана |
| `packages/rfb_session` | сеанс в отдельном потоке: подключение, команды, события, статистика, запуск High Performance; пример `snapshot` |
| `packages/ard_media` | медиапротокол Apple: виртуальный дисплей, предложение и ответ, SRTP, сборка кадров HEVC из RTP, отчёты получателя |
| `packages/hp_media` | сеанс High Performance: UDP-порты 5900 и 5901, восстановление потока, декодирование в полосы картинки |
| `packages/hp_audio` | звук High Performance: порядок пакетов, декодер AAC-ELD, буфер 60 мс с подстройкой скорости, вывод на устройство Windows |
| `packages/nvdec` | декодер HEVC на видеокарте NVIDIA, плоскости YUV в буферах из пула |
| `packages/gpu_scaler` | шейдер YUV → RGB и Display P3 → sRGB, масштабирование кадра на видеокарте |
| `packages/remote_input` | клавиши → keysym, мышь, колесо |
| `packages/platform` | Windows: перехват клавиши Windows, диспетчер учётных данных |

Правила кода: один тип, функция или константа на файл; без комментариев; тесты лежат в `test/<фраза>_test.rs`, по одной функции `test_<фраза>` на файл; логи с тегами `[RFB]`, `[AUTH]`, `[DECODE]`, `[SESSION]`, `[MEDIA]`, `[AUDIO]`, `[UI]`, `[GPU]`.

## Подготовка Mac

Системные настройки → Основные → Общий доступ → включить «Общий экран». Вход — под именем и паролем пользователя macOS, отдельный VNC-пароль не нужен.

## Запуск

```
cargo client-release
```

Или собрать и запустить `target\release\vnc.exe`:

```
cargo build --release -p app
```

В форме указать адрес Mac (например, `192.168.0.220`), порт `5900`, пользователя macOS и пароль. После входа окно подстраивается под экран Mac и встаёт по центру монитора.

## Сборка

- Release (`cargo client-release`, `cargo build --release -p app`) собирается на максимум: `opt-level = 3`, fat LTO, один codegen unit и код под процессор этой машины. Последнее — это `target-cpu=native` в `.cargo/config.toml`, на Ryzen 7 7700 он даёт AVX2 и AVX-512. Такой `vnc.exe` может не запуститься на другом процессоре. Сборка для другого ПК (любой процессор с AVX2): `$env:RUSTFLAGS='-C target-cpu=x86-64-v3'; cargo build --release -p app`, после неё `Remove-Item Env:RUSTFLAGS`, иначе и следующие сборки пойдут с этим флагом.
- `panic = "abort"` не включён: JPEG-декодер и обратные вызовы NVDEC ловят панику, чтобы битые данные не роняли клиент.
- Debug (`cargo client`) собирается быстро и работает почти как release. Зависимости и горячие пакеты (`rfb_decode`, `rfb_session`, `hp_media`, `hp_audio`, `nvdec`, `ard_media`, `gpu_scaler`) идут с `opt-level = 2`. У зависимостей и `rfb_decode` нет debug-assertions и проверок переполнения. Поэтому wgpu не включает отладочный слой DirectX 12, а zlib и JPEG работают как в release. В тестах у `rfb_decode` эти проверки включены. Остальной код без оптимизаций, с номерами строк для трассировок. Отладочный слой wgpu включается так: `$env:WGPU_VALIDATION=1; $env:WGPU_DEBUG=1; cargo client`.
- Линковщик — `rust-lld` вместо `link.exe`. Правка в приложении пересобирается за 1,5 с, правка в `rfb_decode` — за 2 с, release после правки в приложении — за 75 с.
- Иконка `apps/client/assets/vnc.ico` содержит десять размеров, от 16 до 256 пикселей. Скрипт `apps/client/build.rs` встраивает её в `vnc.exe` через `winresource` и `rc.exe` из Windows SDK, вместе с описанием файла «VNC». Окно берёт иконку из ресурсов exe под масштаб монитора: на 100% это 16 пикселей в заголовке и 32 на панели задач.

## Скорость

- «Баланс» и «Быстро» просят у Mac его собственную кодировку Apple MVS (номер 1011, сжатие с потерями блоками 8×8, как JPEG). Полный кадр 3024×1964 весит около 300 КБ и декодируется за 22 мс, обычное обновление области в 1–2 Мп — за 6 мс.
- Следующее обновление запрашивается сразу, как только начинает приходить текущее, поэтому подготовка кадра на Mac и сеть идут параллельно с декодированием.
- «к/с» на панели — сколько обновлений прислал Mac за секунду. Mac шлёт их, только когда его экран меняется: в простое число маленькое, при движении мыши и прокрутке доходит примерно до 60.
- Mac рисует курсор прямо в картинке, отдельной формы курсора в режиме VNC он не присылает.
- «Без потерь» идёт через ZRLE: полный кадр Retina — до 8 МБ и 0,6–0,8 с, поэтому движение заметно дёргается.
- `rfb_decode` и в debug-сборке собирается без проверок переполнения и debug-assertions, поэтому `cargo client` декодирует так же быстро, как `cargo client-release`. Тесты эти проверки сохраняют.

## Режим High Performance

Галочка «High Performance» в форме входа. Она доступна в режиме Apple Remote Desktop и по умолчанию выключена. Под ней галочка «Retina», по умолчанию включена.

- Mac создаёт виртуальный дисплей под окно в 90% монитора Windows (на 2560×1440 окно 2304×1296) и шлёт его видеопотоком HEVC 4:4:4 до 60 к/с по UDP с шифрованием SRTP. Поток декодирует видеокарта NVIDIA.
- С «Retina» Mac рисует два пикселя на пункт, как для штатного клиента Apple: на 2560×1440 это 1920×1080 пунктов и видео 3840×2160. Окно уменьшает картинку фильтром Catmull-Rom, и в окне, и на полном экране. Текст чёткий, интерфейс Mac крупнее.
- Без «Retina» дисплей 2304×1296 пунктов, один пиксель на пункт, картинка в окне 1:1. Места больше, но macOS рисует текст без Retina, и он мягче.
- Дисплей следует за окном. Через секунду после того, как размер окна перестал меняться (перетаскивание края, «Полный экран»), клиент просит у Mac дисплей нового размера и новый поток, не переподключаясь, как штатный клиент Apple и noVNC-ARD. До нового потока на экране остаётся старая картинка.
- Без «Retina» полный экран на 2560×1440 даёт дисплей 2560×1440 и картинку 1:1. С «Retina» дисплей 16:9 уже упирается в 4K (1920×1080 пунктов), поэтому полный экран его не меняет, а другие пропорции окна меняют.
- Пока Mac не ответил на прошлый размер, новый ждёт, и уходит только последний. Смена размера не тратит попытки восстановления потока. Если Mac не ответил на новый размер за 5 с, остаётся старый поток. После переподключения дисплей просится по текущему размеру окна.
- Пока идёт сеанс, экран самого Mac погашен. После отключения он включается снова.
- Видео приходит на UDP-порты 5900 и 5901. При первом запуске брандмауэр Windows спросит разрешение для `vnc.exe`, его нужно дать.
- Mac не рисует курсор в видео, поэтому курсор, как и в обычном режиме, рисует Windows. Форма курсора идёт по TCP. После каждого такого обновления клиент продлевает подписку AutoUpdate, как Apple Screen Sharing, иначе форма курсора замирает. Картинка приходит в пикселях, а курсор в пунктах, поэтому с «Retina» курсор увеличивается на масштаб дисплея.
- Свёрнутое окно не копит память: кадр уходит в видеокарту сразу, не дожидаясь отрисовки.
- Процессор кадр не перебирает. NVDEC декодирует полосу, её плоскости YUV копируются в буфер из пула и без копий доходят до окна. Там шейдер переводит YUV в RGB прямо в текстуру картинки. В видеокарту уходит 3 байта на пиксель при 4:4:4 и 1,5 при 4:2:0 вместо 4.
- Mac шлёт видео в цветах Display P3, а Windows (тем более с включённым HDR) показывает окно как sRGB. Шейдер переводит P3 в sRGB в линейном свете, поэтому цвета совпадают с экраном Mac. Цвета шире sRGB обрезаются до ближайших.
- Звук Mac приходит вместе с видео: AAC-ELD, 48 кГц, стерео, пакет каждые 10 мс. На верхней панели кнопки «Звук: Здесь / На Mac». «Здесь» (по умолчанию) — звук играет на устройстве вывода Windows по умолчанию с задержкой около 60 мс. «На Mac» — клиент звук не играет и отпускает устройство. Выбор сохраняется и действует сразу, без переподключения.
- Попросить Mac играть звук у себя клиент не может: звук идёт в поток High Performance, а играет ли его Mac при этом сам, решает macOS. В обычном режиме звук по VNC не передаётся и играет на самом Mac, поэтому кнопки звука там неактивны.
- Пакеты звука выстраиваются по порядку. Пропавший пакет ждут, пока за ним не придут три следующих (~30 мс), потом закрывают тишиной с плавным затуханием и нарастанием. Если звук в буфере копится или кончается, скорость воспроизведения меняется не больше чем на 0,4%, на слух это незаметно. Больше 150 мс в буфере — лишнее отбрасывается.
- Если в Windows сменить устройство вывода (наушники, колонки), звук переходит на новое за секунду.
- Декодер — Fraunhofer FDK AAC через крейт `fdk-aac`. Его лицензия разрешает личное использование. Если отдавать `vnc.exe` другим, нужно приложить текст лицензии FDK; патентов на AAC она не даёт.
- Когда на экране Mac ничего не меняется, Mac не шлёт видео, а звук идёт дальше. Это покой, поток не перезапускается.
- Поток просится заново, только если картинка не собралась целиком за 3 с или все пакеты пропали на 3 с. Новый поток после перезапуска должен показать картинку за 3 с, иначе просится ещё раз. Причина пишется в лог строкой `[MEDIA] ...: last picture ... ms ago, ...`.
- Если Mac не предлагает High Performance, сеанс идёт в обычном режиме. Если поток обрывается чаще трёх раз за 30 с, клиент через секунду переподключается без High Performance.
- В строке статистики кодировка — «High Performance», кадры в секунду и Мбит/с считаются по видеопотоку.

## Команды

| Команда | Что делает |
|---|---|
| `cargo t` | все тесты (`cargo nextest run --workspace`) |
| `cargo test-rfb` | тесты протокола, входа, декодеров и сеанса |
| `cargo test-client` | тесты клиента, масштабирования, ввода и `platform` |
| `cargo clippy --workspace --all-targets -- -D warnings` | линтер, предупреждения считаются ошибками |
| `cargo client` / `cargo client-release` | запустить клиент (debug / release) |
| `cargo snapshot <адрес> <порт> <пользователь> <файл.png>` | подключиться, сохранить один кадр в PNG и вывести статистику |

Пароль для `snapshot` берётся из переменной `VNC_PASSWORD`:

```powershell
$env:VNC_PASSWORD = "<пароль>"; cargo snapshot 192.168.0.220 5900 <пользователь> mac.png; Remove-Item Env:VNC_PASSWORD
```

## Тесты

Тесты запускаются через cargo-nextest, настройки — в `.config/nextest.toml`.

- Протокол, вход и сеанс проверяются на поддельном сервере, который тесты поднимают на `127.0.0.1`.
- Декодеры получают испорченные данные: сеанс должен закончиться ошибкой, без паники и без огромных выделений памяти.
- `gpu_scaler` рисует на настоящей видеокарте.
- `platform` записывает временный пароль в диспетчер учётных данных и удаляет его.
- Звук проверяется без устройства вывода: порядок пакетов, декодер, буфер и пересчёт частоты считаются на данных из тестов.

## Настройки

Файл `%APPDATA%\vnc\settings.json` создаётся при первом подключении. Испорченный файл не мешает запуску: берутся значения по умолчанию.

| Поле | По умолчанию | Значение |
|---|---|---|
| `host` | `""` | адрес Mac |
| `port` | `5900` | порт |
| `username` | `""` | пользователь macOS |
| `remember_password` | `true` | хранить пароль в диспетчере учётных данных Windows |
| `scale_mode` | `"fit"` | `"fit"` — по окну, `"actual"` — 1:1 |
| `quality` | `"balanced"` | `"lossless"`, `"balanced"`, `"fast"` |
| `sound` | `"here"` | звук High Performance: `"here"` — играть на этом ПК, `"mac"` — не играть здесь |
| `swap_control_and_command` | `false` | поменять Ctrl и Cmd |
| `grab_keyboard` | `true` | клавиша Windows работает как Cmd |
| `clipboard_sync` | `true` | общий буфер обмена |
| `apple_remote_desktop` | `true` | режим Apple Remote Desktop: протокол Apple, курсор Mac рисует Windows |
| `high_performance` | `false` | видеопоток High Performance, экран Mac гаснет на время сеанса |
| `retina` | `true` | High Performance с двумя пикселями на пункт: чёткий текст, интерфейс Mac крупнее |

Пароль в файл не пишется. Он хранится в диспетчере учётных данных Windows под именем `vnc:<пользователь>@<адрес>:<порт>`: сохраняется после успешного входа и удаляется, если снять «Запомнить пароль».

Журнал — `%APPDATA%\vnc\vnc.log`, перезаписывается при каждом запуске.

## Клавиатура и мышь

- Буквы и знаки печатаются в раскладке Windows: язык переключают в Windows (Alt+Shift или значок языка на панели задач), раскладка Mac на набор не влияет. Сервер Apple печатает ровно тот символ, который получил, поэтому кириллица уходит символами Юникода.
- Сочетания с Cmd, Ctrl и Option идут по физическим клавишам US: Cmd+C и Cmd+V работают и в русской раскладке.
- Клавиша Windows работает как Cmd, пока клиент подключён и его окно активно: «Пуск» не открывается, Win+Пробел не переключает раскладку Windows (на Mac это Cmd+Пробел).
- Alt — это Option. Кнопка «Поменять Ctrl и Cmd» на панели меняет местами Ctrl и Cmd: Ctrl+C и Ctrl+V копируют и вставляют на Mac, а клавиша Windows работает как Control.
- Ctrl+Alt+Del, Win+L и Alt+Tab остаются у Windows, Alt+F4 закрывает клиент.
- Если окно теряет фокус, зажатые клавиши и кнопки мыши отпускаются на Mac.
- Курсор Mac показывается курсором Windows и масштабируется вместе с картинкой. Mac шлёт курсор в пунктах и сообщает, сколько пикселей в пункте его экрана, поэтому на Retina-экране курсор увеличивается во столько же раз. Форма масштабируется усреднением по площади, края и обводка остаются гладкими.

## Буфер обмена

- Текст, скопированный на Mac, попадает в буфер Windows.
- Текст из буфера Windows уходит на Mac при подключении и каждый раз, когда окно клиента снова становится активным.
- Протокол VNC передаёт текст в Latin-1, поэтому кириллица из Windows доходит до Mac как «?». Картинки и файлы не передаются.

## Панель и переподключение

- Панель появляется, если подвести мышь к верхнему краю окна: «По окну» / «1:1», «Качество» (Без потерь, Баланс, Быстро), «Поменять Ctrl и Cmd», «Полный экран», «Обновить», «Отключиться» и статистика (кадры в секунду, Мбит/с, кодировка).
- Если связь пропала после входа, клиент переподключается сам: через 1, 2, 5 с, дальше каждые 10 с, пока не нажата «Отмена». Последний кадр остаётся на экране.
- Неверный пароль не повторяется: клиент возвращается к форме и показывает сообщение.

## Благодарности

Декодер Apple MVS (`packages/rfb_decode/src/mvs`) перенесён на Rust с JavaScript-декодера проекта [noVNC-ARD](https://github.com/peetinc/noVNC-ARD) (лицензия MPL-2.0). Файлы этого декодера — производная работа и распространяются на условиях MPL-2.0.
